# 0030 — Podman owns container builds and Compose orchestration

- **Status:** Accepted
- **Date:** 2026-09-26
- **Deciders:** Chandra

## Context

The deployment assets were Docker-branded end to end: `docker-compose.yml`
(+ `.gpu.yml`), three `Dockerfile`s, `.dockerignore`, `docker compose`
commands in `scripts/`, `${DOCKER_*}` compose interpolation variables, and
`host.docker.internal` defaults for reaching host Ollama/Docling.

Docker was never actually installed on the development laptop, and the engine
chosen for local work is Podman: rootless by default, daemonless, and a
first-class `podman compose` entry point that delegates to a Compose provider.
Ubuntu 24.04 ships Podman 4.9 in its own repositories, and the newest
`podman-compose` provider is installable per user through pipx.

GPU passthrough differs between the engines. Docker consumes the
`deploy.resources.reservations.devices` NVIDIA reservation through the
NVIDIA Container Toolkit runtime; Podman consumes a CDI spec
(`/etc/cdi/nvidia.yaml`) generated by `nvidia-ctk cdi generate` and takes a
plain CDI device name.

## Decision

- Podman (rootless) is the supported container engine; `podman compose` with
  the pipx-installed `podman-compose` provider is the orchestration entry
  point. `./scripts/setup_podman_host.sh` performs the one-time host setup
  (engine packages, subordinate UID ranges, provider, NVIDIA CDI).
- Docker-branded file names are replaced with Podman-native ones:
  `deploy/compose/compose.yaml` (+ `compose.gpu.yaml`), `Containerfile` in the
  API and both sidecars, and `.containerignore`. The compose-spec build key
  stays `dockerfile:` (that is the spec's field name, not an engine
  reference).
- Host services are reached through Podman's built-in
  `host.containers.internal`; the compose interpolation variables are renamed
  `${DOCKER_*}` → `${HOST_*}`.
- The GPU overlay passes `devices: ["nvidia.com/gpu=all"]` (CDI) instead of
  the Docker NVIDIA device reservation, and requires
  `sudo nvidia-ctk cdi generate --output=/etc/cdi/nvidia.yaml` first. The base
  stack remains CPU-only; laptop GPUs that share VRAM with host Ollama keep
  the GPU reranker opt-in.
- The Python benchmark scripts sample memory via `podman stats` and resolve
  Compose container IDs with `podman compose ps -q`.

## Consequences

- No Docker daemon, socket, or root-privileged engine runs on the dev laptop;
  containers run mapped to the invoking user and images live under
  `~/.local/share/containers`.
- The Docker Desktop path is gone. Linux is native; macOS and Windows go
  through a `podman machine` VM, where `host.containers.internal` still
  reaches host Ollama. The GPU overlay stays Linux/WSL2-only.
- Historical ADRs (0003, 0008, 0021, 0022, 0023) keep their Docker-era
  wording as records of their time; this ADR governs current practice.
- `.github/dependabot.yml` keeps `package-ecosystem: docker` for
  `/deploy/compose` — that ecosystem tracks image references in Compose files
  and Containerfiles regardless of the engine.

## Maintenance, October 5, 2026

The Python API/sidecar benchmark scripts were retired after a verified backup.
API performance now uses the [Locust suite](../../benchmark/README.md), which
records available API process metrics. It does not sample container RSS/VRAM.
The Podman build and deployment decisions above remain in effect.
