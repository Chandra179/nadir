# Streaming answers + rewrite in the Think trace

Two features, one restructure of the chat turn flow:

**Today:** `POST /retrieval/search` runs the whole turn synchronously — rewrite (result discarded), retrieve, buffer the full Ollama token stream via `io.ReadAll`, render one HTML fragment, persist detached.

**Target:** `POST /retrieval/search` runs rewrite (captured) + retrieval + prompt build, renders the turn fragment immediately with the rewrite step shown in the Think block and an SSE placeholder for the answer; the browser streams answer tokens live from a new SSE endpoint; the turn is persisted when the stream completes.

## 1. Chat domain (`internal/chat/`)

**`chat.go`** — extend `Result`:
- `RewrittenQuery string` — set only when the rewriter actually changed the query (empty = first turn / disabled / failure / unchanged).
- `AnswerStream io.ReadCloser` (with `json:"-"`) — open Ollama token stream handed to the API layer; nil in every non-streaming case (generator disabled, start failure, no chunks).

**`service.go`**
- `Ask`: where `retrievalQuery` is computed, set `res.RewrittenQuery = rewritten` when `rewritten != req.Query`. Replace `generateAnswer` (the `io.ReadAll` buffering) with a stream handoff: `prompt, reader, err := d.generator.Generate(...)` → on error set `res.GenerateError` (unchanged semantics); on success set `res.Prompt = prompt`, `res.AnswerStream = reader` and return — **no server-side buffering anymore**.
- Export `PersistTurn(ctx, req, res, failed) error` = the current `persist` body minus the goroutine (the SSE handler calls it after the stream ends; `persist()` stays as the detached wrapper for the search-failure path, now delegating to `PersistTurn`).
- `rewriteQuery` unchanged (it already returns the rewritten query; Ask now captures it).

## 2. History (`internal/history/service.go`)

Add `RewrittenQuery` to `Turn`; write `"rewritten_query"` in `turnPayload`, read it in `turnFromPayload` (missing key → empty string, so old persisted points replay fine). Thread through `chat.persist`/`PersistTurn`.

## 3. API layer (`internal/api/`)

**`pending.go` (new)** — in-memory registry of pending answer streams: `Put(reader io.ReadCloser, req chat.Request, res chat.Result) (id string)` using crypto/rand UUID, `Pop(id)` (delete-on-connect, single consumer), lazy expiry (~2 min) that closes leaked readers. Transport concern → lives in api, not chat.

**`chat.go`**
- `turnView` += `RewrittenQuery`, `StreamURL`.
- `turnViewFromResult`: map `RewrittenQuery`; if `res.AnswerStream != nil`, `id := d.pending.Put(res.AnswerStream, req, res)` and set `StreamURL = "/retrieval/answer/" + id`.
- New handler `RetrievalAnswer` (SSE): `Pop` the entry → `Content-Type: text/event-stream`, no-cache; loop reading tokens from the stream, writing per-token events and `c.Writer.Flush()` per event; accumulate the full answer; on EOF emit `done` and call `chat.PersistTurn` with the completed `Result` (Answer/HasAnswer filled, stream field cleared); on mid-stream error emit `generror` and persist with `GenerateError` (matches buffered-path semantics). Event format: `event: token` + `data:` lines (HTML-escape each token; split token newlines across multiple `data:` lines per the SSE spec so htmx renders them verbatim).

**`router.go`** — `RouteRetrievalAnswer = "/retrieval/answer/:id"`, `GET`.

## 4. Middleware + server timeouts

- `internal/middleware/timeout.go`: exclude paths prefix `/retrieval/answer/` from the 30s deadline (same pattern as `POST /ingest`) — a stream longer than 30s must not be cancelled.
- `config/config.yaml`: `http.write_timeout: 35s` → `0` with a comment — the server-level write deadline would otherwise kill any answer stream past 35s. (Read/idle timeouts unchanged; generation is still bounded by the generator's own 120s client timeout.)

## 5. Dashboard

**`search.html`**
- Load the htmx SSE extension: `<script src="https://unpkg.com/htmx.org@2.0.4/dist/ext/sse.js" defer></script>`.
- Small inline JS addition: listen for `htmx:sseMessage`; on `done`/`generror` → remove the streaming cursor state, `htmx.trigger(document.body, 'nadir:turn-appended')` (sidebar refresh moves from POST-time to stream-completion time), scroll reader to bottom.

**`turn.html`**
- Think block renders whenever `HasAnswer || StreamURL || GenerateError` (not only `HasAnswer`).
- First line inside Think: **Rewrite row** — `Rewrite · "raw query" → "rewritten query"` (mono style like the Tool row's Search button), rendered only when `.RewrittenQuery` is set; replay gets it for free via `historyTurnToView`.
- Answer area: static `<p>{{.Answer}}</p>` when `HasAnswer` (history replay path); otherwise when `StreamURL`: an `hx-ext="sse" sse-connect="{{.StreamURL}}"` container holding the streaming `<p sse-swap="token" hx-swap="beforeend">`, a hidden `sse-swap="generror"` error slot, and the done target.
- Tool block's Inspect `<pre>` additionally shows the effective search query (`"rewritten"` line) when present.

## 6. Tests

- `internal/chat/chat_test.go`: fake generator now returns an `io.Pipe`-based reader; update assertions that relied on buffered `Result.Answer`; new cases — rewritten query captured in `Result`, stream handed off unbuffered, generation start failure → `GenerateError` with nil stream.
- `internal/api`: httptest for the SSE endpoint — put a pipe in the registry, read the token/done events, assert the fake history's `AppendTurn` received the full answer; a mid-stream-error case asserting `GenerateError` persistence.

## Consequences / trade-offs (accepted)

- Turn persistence moves to stream completion: a turn whose SSE is never consumed (browser closed instantly) is dropped after registry expiry — logged, not persisted.
- `POST /retrieval/search` responds as soon as retrieval finishes; the answer area streams. History replay, semantic cache, rewrite fallback semantics, and the eval A/B path are untouched.
- AGENTS.md's chat flow line updated: "buffered generate → detached persist" → "SSE answer stream → persist on completion".
